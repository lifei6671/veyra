# Code Delivery Review

对用户指定的代码、diff、PR 或当前任务做只读审查，找出会影响实际行为的缺陷。以当前用户要求、仓库规则和真实代码为准；不要求冻结交付包、流程状态文件或历史 UI 批准工件。

## 工作方式

1. 确认审查范围与当前版本，包含相关未跟踪文件和删除项；保留无关用户改动。
2. 阅读受影响的调用关系、状态/数据契约与测试。按实际风险选择关注面，不机械扩展全仓或要求增加抽象。
3. 检查需求是否实现、关键失败路径是否正确，以及已执行验证能支持哪些结论。未执行和环境受限如实说明，不伪造通过。
4. UI 检查实际操作、必要状态、浅深色和截图；缺少真实界面证据时说明验证范围，不要求固定格式的人工批准文件。
5. 修复后只复查受影响问题与集成边界，不因轮次或流程工件缺失停止有依据的审查。

复杂改动按需读取 [关注面索引](references/review/INDEX.md)；语言相关风险按 [语言索引](languages/INDEX.md) 选择。它们只补充审查内容，不决定任务状态、强制并行或新增审批流程。

## 返回结果

先列可操作的问题：严重度、文件位置、触发条件、用户影响和最小修复方向。没有可信问题时直接说明未发现问题，并列出实际验证及明确限制。

审查不自动修改实现或任务状态，不提交、推送或发布。若是实现者自查，说明自查；不要声称是独立审查。仅按用户或适用规则的明确要求委派其他审查者。
