# P7 数据与发布收尾

[长期开发规范](DEVELOPMENT_WORKFLOW.md) · [任务总表](IMPLEMENTATION_PHASES.md) · [当前交接](SESSION.md) · [方案](../openbox-rust-gpui-implementation-plan.md)

**里程碑范围**：目标是可恢复的数据操作、可验证的 GitHub 安装包和完整证据；备份等主要持久配置 schema 稳定，重置等生命周期/网络清理。发布准备与实际发布分开记录。阶段不作统一 Gate；以下各卡的显式依赖独立决定 READY。

**2026-10-08 分期适用范围**：遵循[唯一调度政策](DEVELOPMENT_WORKFLOW.md#delivery-order-20261008)。P7-01 在原 schema 依赖全部满足后可于系统能力前完成真实业务备份/导入：自己拥有的临时目录内，以生产 schema 写出备份、读入/预览/校验/导入，重建 Service/Store 从磁盘核对字段/版本/epoch/重映射引用及失败保旧，不以 Mock/样本文件替代真实 roundtrip；本地业务与局部 150% 浅色先验，其它主题/缩放/原生文件对话框全流程留 P7-04。P7-02 保留系统恢复依赖，P7-03 仍负责最终批次的包构建/升级演练；P7-04 统一实际 GUI E2E，P7-05 才给最终包结论。全部原数据排除项、清理失败停止删除、安装保护和发布授权规则保留；延期项记 NOT_RUN/承接卡，不把计划或假加载记 DONE。最终 E2E/包复验以各前期卡已完成真实业务及局部定向集成为基础，不替代它们的功能验收；P7-01 本地 schema 写读与重建验证仍在本卡前期完成。

<a id="obg-p7-01"></a>
## OBG-P7-01 备份、预览与原子导入

**类型**：数据与 UI；**依赖**：OBG-P1-02、OBG-P1-04A、OBG-P1-04B、OBG-P1-05、OBG-P3-06、OBG-P4-01、OBG-P4-03、OBG-P4-05B、OBG-P4-06、OBG-P5-02、OBG-P5-04、OBG-P5-06。**依据/范围**：方案 §8.8、§12；core backup/importer、后端数据设置；API 22–23。

**泳道 / 写范围**：Core/Config + GPUI；backup/importer 与数据 UI；全局 schema/epoch 交 owner。

**执行与交付**：先核对主要持久配置 schema 已稳定（Preferences、订阅/组/failover/chain、Routing/Terminal、DNS/filter、Shared Inbound、Subscription Share、统计保留，以及由 P1-02 提前定义的版本化 AppConfig 桌面 update preference〔如适用〕），登记 schema 版本和引用映射；schema 前置只针对持久业务数据定义，原生文件操作复用 P1-05。不等待 P6-03 登录启动或 P6-04 Updater 行为完成。新备份格式与 OpenBox/旧 Veyra 独立 importer、原生保存/读取、内容预览、订阅 replace/append、引用 ID 重映射和可选刷新。

**验收**：

- [ ] 预览/校验失败不写入；整体提交原子，append 重映射所有相关引用，replace 创建新 epoch。
- [ ] 导入后用新 ID 刷新；刷新部分失败不撤销已导入静态配置；旧任务不能写回新状态。
- [ ] 仅包含可迁移业务配置与已确认选择；OS 登录项/注册状态、运行中 updater 状态、pending、实例/进程身份、运行缓存或可直接启动 manifest 不进入业务备份；业务备份与脱敏诊断明确区分。
- [ ] 版本化桌面 update preference（如适用）按早期 AppConfig schema 备份/恢复，导入不声称已注册 OS 登录项或完成更新安装；主题/背景/配置刷新无需浏览器 reload；预览、选择、取消、错误和浅深色通过验收。

## OBG-P7-02 诊断导出与恢复出厂

**类型**：维护服务与 UI；**依赖**：OBG-P7-01、OBG-P6-02、OBG-P6-03、OBG-P2-07、OBG-P5-06。**依据/范围**：方案 §8.8、§13；core diagnostics/maintenance、后端数据设置；API 20、24。

**泳道 / 写范围**：Runtime/Platform + GPUI；maintenance/脱敏 diagnostics、重置 UI 与资源清理。

**执行与交付**：先确认 P6-02/03 生命周期与统一退出、P2-07 网络恢复和 P5-06 分享清理契约可用；定义诊断 schema、脱敏导出、版本/操作/能力和恢复记录摘要；恢复出厂 10 秒倒计时及停止→网络恢复→删除→首次使用流程。

**验收**：

- [ ] 诊断不含可用密码/token/URL 凭据/私钥；结果不完整时明确说明。
- [ ] 倒计时/确认可操作；停止或恢复网络失败时终止删除并保留归属材料。
- [ ] 成功重置仅删除本应用数据/缓存/token，旧分享入口失效，进入新的状态 epoch。
- [ ] 导出/重置成功和失败的真实操作与 界面检查通过，不在用户正式数据上做破坏性验证。

**类型**：发布工程；**依赖**：OBG-P7-01、OBG-P7-02、OBG-P6-05。**依据/范围**：方案 §8.8、§14、§16；构建脚本/CI、应用资源与安装包。

**泳道 / 写范围**：Runtime/Platform；发布脚本/CI、资源清单与安装说明。

**执行与交付**：绑定源码/锁文件/应用/helper/内核/资源版本；实现已选架构的可复现构建、无发布签名安装包与摘要；检查最低 ad-hoc 运行要求，执行手动更新成功/失败/回退。

**验收**：

- [ ] 包内容、架构、最低运行签名状态与版本清单可对应；没有 Developer ID/公证也可按说明从真实下载包打开，不关闭系统保护。

- [ ] 新安装/升级后配置、选择、必要缓存和 helper 版本符合预期；旧 schema 回退边界明确。
- [ ] 仅使用验证后的候选包；上传、发布或修改生产渠道需当前明确授权。
